## **32.1 Overview**

This project seeks to build out an agentic AI solution for finding grants.gov solicitations and building teams of VT faculty from the College of Science (CoS) that could apply for, receive funding, and implement an effective research program. For now, the solution is limited to CoS but should extend to other VT colleges (for interdisciplinary solicitations).

## **32.2 Requirements & Resources**

- 1. The application should query the REST API from grants.gov to pull currently open solicitations from all programs. Closed solicitations can be archived but should not be shown to the user. This application is about building teams for net-new solicitations, not managing the research portfolio.
- 2. [authors.csv.zip](https://ads1.datasci.vt.edu/ads_5984/projects/grant_teams_midterm_project/authors.csv.zip) contains a list of CoS faculty with important metrics (such as the H5 index). This file was generated through work done by the VT library. There is a VT website, but it is not made available to students (at this time).
- 3. [publications.csv.zip](https://ads1.datasci.vt.edu/ads_5984/projects/grant_teams_midterm_project/publications.csv.zip) contains all the research publications for CoS faculty members (including abstracts). This file was sourced from the Elsevier API (all VT students have access to the API via an API key they generate). Initial prototypes can use the .csv file, but the final product should use the API directly.
- 4. Teams generated by the tool must be reproducible, explainable, and rational (i.e. easily defended), based on a holistic understanding of publications and faculty metrics. This is a non-trivial ask!

## **32.3 Use Cases**

- 1. A user should be able to pull the latest grants.gov solicitations (update the local database). Then the user should be able to filter/sort the solicitations by type, date, amount, etc.
- 2. The user should be able to select a solicitation and click a button to build a team .
- 3. After a user clicks build a team , they should be transferred to a chatbot interface (with RAG) that automatically builds a team based on a user-defined prompt template + RAG content.
- 4. The user can follow up on this initial generation.

## **32.6 Questions for Consideration**

- 1. What is an optimal team?
- 2. What is the parsimonious (agentic or not) design to implement this solution?
- 3. RAG or GraphRAG?
- 4. What are the LLM and RAG limitations that might make our teams non-optimal?
- 5. How do we generate optimal teams using LLMs and RAG? There are many limitations we must overcome. Can we address them with agentic design patterns?
- 6. How do we balance generation costs with optimal outcomes?

#### **32.7.5 5. RAG / GraphRAG database**

The chosen retrieval approach drives the database:

**RAG (vector search):**

[ChromaDB](https://docs.trychroma.com/) is a strong option — embed faculty publication abstracts and metadata, then retrieve by semantic similarity. Runs locally (no API key) with a simple Python client or a persistent server.

**GraphRAG:**

[Neo4j](https://neo4j.com/download/) is a strong option for modeling faculty, departments, publications, and keyword/collaboration relationships explicitly, queried via Cypher (no API key — local Bolt connection, run via Docker).

A hybrid of both is also viable. See the **Questions for Consideration** section above ("RAG or GraphRAG?").
